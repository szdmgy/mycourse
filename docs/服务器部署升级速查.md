# 服务器部署升级速查（Windows 局域网）

适用项目：**mycourse**（实验报告收集系统）  
适用脚本：仓库根目录 **`mycourse_deploy_update.bat`**

## 0. 前提条件

- 服务器已安装 **Git** 与 **Python 3.10+**
- 能访问 Git 远程仓库（默认配置为 `https://github.com/szdmgy/mycourse.git`，私有库需本机已配置凭据）
- 已准备好生产用 **`db.sqlite3`**；**`.env`** 可与 `.env.example` 一致（复制为 `.env` 即可满足脚本检查）

## 本仓库目录说明

- **Git 仓库根目录**：含 `.git`、`README.md`、子文件夹 `mycourse/`  
- **Django 根目录（manage.py 所在）**：`mycourse/mycourse/`  
- 脚本会自动在 Git 根目录执行 `git pull`，在 Django 根目录执行 `venv`、**`migrate`**、**`collectstatic`**

## 1. 首次部署（克隆 → 复制数据 → 再跑一次脚本）

1. 将 `mycourse_deploy_update.bat` 放到目标父目录（如 `D:\apps\`）  
2. **第 1 次**双击运行，输入 `Y` 确认（脚本会克隆出 `D:\apps\mycourse\` 并在 **`mycourse/mycourse/`** 下创建 **`venv`**、安装依赖）**此时不会执行 migrate**（因为还没有数据库文件）  
3. 将 **`db.sqlite3`** 复制到 **`D:\apps\mycourse\mycourse\mycourse\`**（与 `manage.py` 同级）；在同目录将 **`.env.example` 复制为 `.env`**（或自建 `.env`）  
4. **第 2 次**双击同一脚本并输入 `Y`：脚本进入升级流程，在拉取最新代码、更新依赖后，对刚复制的 **`db.sqlite3` 自动执行 `migrate --noinput`**，再执行 **`collectstatic`**  

**说明：** 若当前代码比旧库更新、带有新的迁移文件，正是这**第二次执行**里的 **`migrate`** 把数据库结构升级到与代码一致；无需再单独手工迁移（除非你选择下面的「仅迁移」方式）。

## 1.1 可选：已拷好库、只想先迁移、暂不 git pull

在服务器 **`mycourse/mycourse/`** 下：

```bat
venv\Scripts\activate
python manage.py migrate --noinput
python manage.py collectstatic --noinput
```

生产环境仍建议用脚本第二次完整升级，以便代码与依赖与线上一致。

## 2. 日常升级（1 步）

- 本地开发并 `git push` 后，在服务器上双击 **`mycourse_deploy_update.bat`**（放在 **Git 仓库根目录** 与首次克隆结果一致），输入 **`Y`** 即可。

脚本会自动执行：

- 在 **Git 根目录**：`git fetch` / `git checkout` / **`git pull --ff-only`**
- 在 **`mycourse/mycourse/`**：更新 **`pip install -r requirements.txt`**
- **`python manage.py migrate --noinput`**
- **`python manage.py collectstatic --noinput`**

升级前会检查 **`mycourse/mycourse/`** 下存在 **`.env`** 与 **`db.sqlite3`**（与全局规则 Y12 对齐）。

## 3. 启动服务

- 本地调试：仓库根目录 **`run_local.bat`**（端口 **9900**）  
- 生产：`mycourse/mycourse/start_server.bat`（默认 **8001**，Waitress）

## 4. 脚本配置项（按需修改）

用记事本编辑 `mycourse_deploy_update.bat` 顶部：

| 变量 | 说明 |
|------|------|
| `REPO_URL` | Git 克隆/拉取地址 |
| `BRANCH` | 分支名（当前默认 **master**） |
| `PY_CMD` | Python 启动方式，如 `py -3` 或 `python` |
| `DJANGO_SUBPATH` | 一般无需改（本仓库为 `mycourse\mycourse`） |
| `VENV_NAME` | 与现有脚本一致，默认 **venv** |

## 5. 常见问题

- **缺少 `.env` 或 `db.sqlite3`**：放到 **`mycourse/mycourse/`**（与 `manage.py` 同级），不是仓库最外层  
- **`git pull --ff-only` 失败**：Git 根目录存在未提交改动，先在该目录 `git status` 处理  
- **Python 不可用**：修改 `PY_CMD=python` 或安装 Python Launcher
